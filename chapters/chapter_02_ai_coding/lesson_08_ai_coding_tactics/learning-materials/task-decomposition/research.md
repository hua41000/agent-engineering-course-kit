# 任务拆解与执行节奏控制：研究结论

初次研究日期：2026-10-15；大需求分层与任务粒度补充核验：2026-10-18。消费文件：[best_practices.md](best_practices.md)。

2026-10-18 的七条选编与新增来源见[补充研究](#large-requirement-decomposition)。下文原 R1—R8 与 S1—S10 保留初次研究记录；其中的最佳实践字母是当时编号，当前编号以补充研究中的映射为准。

本次核验了工程师本人工作流、失败复盘，以及 Anthropic、Cursor 的官方工程分享。以下区分来源记载、教学提炼和适用边界；教学案例均为自拟示例，未在本次调研中运行。材料支持具体做法，无法据此宣称统一的提效比例或最优任务时长。

## 研究结论

<a id="r1"></a>
### R1：先消除会改变方案的不确定性，再排实施任务

- **来源记载**：Anthropic 建议对复杂改动先探索、再规划、再实施；同时明确，小且清楚的改动可以直接执行。Harper Reed 在既有项目中按当前任务规划，避免为整个项目重做计划。[S1](#s1) [S2](#s2)
- **教学提炼**：涉及陌生模块或跨模块行为时，先找入口、约束和已有实现，再写实施顺序。可把未知问题单独列为一个调查任务，交付明确答案和依据。
- **边界**：没有证据支持每个修改都先生成长篇方案。文案修正、明确的小修复应保持轻量。

<a id="r2"></a>
### R2：用可验收行为定义一个切片

- **来源记载**：Anthropic 的长任务实验观察到模型一次承担过多功能、半途耗尽上下文，以及过早宣布完成。其改进采用带操作步骤的功能清单，并要求一次推进一个功能。[S3](#s3)
- **教学提炼**：把“做导出功能”拆成“给定数据与筛选条件，用户能下载内容正确的文件”等可观察结果；每个切片包含验收方式，再确定涉及哪些层和文件。
- **边界**：该实验面向全栈 Web 应用。通用迁移、构建修复等任务可以用兼容性检查或构建结果验收，无须强行包装成 UI 功能。

<a id="r3"></a>
### R3：按依赖排序，每步保留集成结果

- **来源记载**：Harper Reed 的实际规划提示要求步骤递进、复杂度逐步增加，并在每一步接入已有结果，避免遗留未接线的代码。[S2](#s2)
- **教学提炼**：先识别共享输入输出与前置能力，再排下游任务；任务单应写出“依赖什么、产出什么、如何接入”。接口不确定时先验证接口。把路由到处理逻辑的连通检查放在早期切片中。
- **边界**：明确共享接口属于课程实施建议，来源没有证明某一种接口文档模板最好。实现中发现新事实可以调整接口，并同步受影响任务。

<a id="r4"></a>
### R4：粒度以可理解、可验证为准，检查点按风险安排

- **来源记载**：Addy Osmani 根据自己的项目经历建议逐块实施与测试，块的大小应允许模型处理，也允许人理解。Jesse Vincent 的一线工作流把任务写明文件与测试方式，再按小批次交由另一会话审查。[S4](#s4) [S5](#s5)
- **教学提炼**：一次任务聚焦一个可说清的变化；初次接触模块时缩小批次，稳定重复任务可扩大批次。审查重点落在共享接口、数据迁移和首个完整流程等关键变化之后。
- **边界**：Jesse 文中的批次数是个人操作样例。Cursor 2026 年的工程复盘也描述了逐步减少逐任务强制动作的过程。没有统一的“每次几分钟、几个文件、几百行”阈值。[S10](#s10)

<a id="r5"></a>
### R5：开始前建立基线，每个切片完成后取得反馈

- **来源记载**：Simon Willison 介绍了在既有项目的新会话里先运行测试的习惯，帮助 Agent 认识测试入口与项目。Harper 的执行节奏是运行代码与测试，通过后再进入下一步。[S6](#s6) [S2](#s2)
- **教学提炼**：先分清已有失败和新增失败；切片内运行直接相关检查，关键接入点验证实际流程，交付前完成仓库要求的回归。测试范围由变更影响决定。
- **边界**：分层检查是教学安排，来源没有比较各种检查顺序的收益。环境缺失和已有失败应如实记录，不能假定基线已经通过。

<a id="r6"></a>
### R6：完成一个切片时，同时留下运行证据与接续位置

- **来源记载**：Anthropic 实验用 Git 历史和进度文件帮助下一会话接续，并要求结束时保持可继续开发的状态。Simon 强调交付时提供实际运行证据，同时保留自动化回归检查。[S3](#s3) [S7](#s7)
- **教学提炼**：进度记录写清完成行为、验证结果、未解决问题和下一项任务；状态勾选应跟随验收。需要切换会话时，保存当前代码与这些信息。
- **边界**：提交频率应服从项目约定；进度文件也应复用项目已有入口，避免并行维护多套状态。截图能说明交互表现，不能覆盖所有业务正确性。

<a id="r7"></a>
### R7：发现前置假设失效，先更新计划再继续扩展

- **来源记载**：Cursor 的动态规划分享主张计划随代码探索和用户意图更新；偏离轨道时，可回到计划修正方向，再执行。[S8](#s8)
- **教学提炼**：当数据字段、接口能力或运行限制与预期不同，暂停受影响任务，补上调查或替代方案，调整依赖和验收，再继续实施。保存决策及依据，防止后续任务沿用旧假设。
- **边界**：实施路径可以调整；用户目标、验收范围或外部接口的实质变更仍须由相应负责人决定。微小实现细节无需变成逐项人工审批。

<a id="r8"></a>
### R8：把“越做越难解释”当作收缩任务的信号

- **来源记载**：Alberto Fortin 复盘 SaaS 基础设施重写时，描述了持续生成代码、修好一处又破坏别处，以及重复服务和命名不一致的问题。他后来放慢扩展，理解并整理实现，再把 AI 用于更明确的小任务。[S9](#s9)
- **教学提炼**：一旦无法解释某个改动如何解决问题，或连续修复扩大影响面，就先停止增加功能，回到最近可解释的结果，补复现与检查，再重新拆分。
- **边界**：这是作者特定项目的失败经历，受其对新技术栈熟悉程度等因素影响，不能外推为所有大任务都会失败，也不能证明某个工具普遍不可用。

## 仍需课堂实测的问题

当前证据未确定统一的最优粒度或检查频率。可用同一项有明确验收标准的改动，对比整包执行和分切片执行，记录返工、检查成本与人工理解难度；本次调研未运行该实验。依赖接口的模板、任务单字段和案例步骤是教学提炼，使用前应结合具体项目裁剪。

## 2026-10-18 补充研究：大需求分层与任务粒度

研究问题：拿到大需求后，如何拆成可执行的子任务，同时兼顾效率、质量和进度可见性；拆到什么程度可以停止。此次打开一手来源正文核验，未运行 Coding 对照实验。

当前选编关系：原 C → 当前 B（探索）、原 D → 当前 C（业务切片）、原 F → 当前 E（共享前置与依赖）、原 B → 当前 F（滚动细化）、原 G → 当前 G（缺陷修复）。新增当前 A（分层与依赖）和 D（粒度判据）。首轮曾将原 E 保留为任务交接条目；经课程负责人指出主题偏离，现以共享前置与依赖拆分替换，依据已有 R3、S2、S14。原 A、E、H、I、J 不进入当前七条主干，旧条目可在 Git 历史中追溯。

### R9：用浅层任务结构保留大需求全貌，用依赖和验收结果掌控进度

- **来源事实**：Spec Kit 的 Spec of Specs 先建立子功能路线图，记录边界、依赖、状态，再分别细化子功能；该文明确要求优先使用较轻的策略，只有更小范围仍过于复杂时才继续递归。[S11](#s11) Anthropic 的长任务实验用功能清单、验证结果和进度记录减少遗漏与过早完成声明。[S3](#s3)
- **发现**：平铺的实施清单不足以同时表达整体交付范围、工作先后和已经完成的能力。路线图与子任务的关联能保留这些信息。
- **教学主张**：采用“需求 → 可验收里程碑 → 子任务”的轻量结构；任务标明归属、前置依赖和产出，里程碑设集成检查点。汇报已验收能力、当前工作和阻塞，避免直接把待办完成比例等同于整体交付比例。消费者：当前最佳实践 A。
- **边界与区别**：这三级结构及进度表达是课程综合方法。里程碑内部允许有按契约划分的技术子任务，子任务可以依赖已完成结果；独立验证不要求零依赖。现有任务表足够时直接复用，不强制建立多份规格。当前 F 解决何时细化后续工作，A 解决大需求怎样组织及如何显示依赖与进展。

### R10：按完整变更与审查负担校准粒度，同时检查过大和过细

- **来源事实**：Google Small CLs 将合适大小定义为自成一体的变更，要求包含相关测试、保持系统可工作，并指出缺少使用场景的过细拆分会妨碍理解。[S12](#s12) Harper Reed 在本人 AI Coding 规划流程中反复拆分与检查步骤，要求安全实施和实际进展兼顾。[S2](#s2)
- **发现**：行数、文件数或执行时长只能提示复杂度，无法单独定义任务边界。一个完整变更可以跨文件，一个文件也可能混有多个可分离目标。
- **教学主张**：检查目标是否聚焦、前置依赖是否明确、当前结果能否验证、完整差异能否审清。多个可分离目标或过大的理解负担提示继续拆；只剩变量、方法、导入等机械动作且无独立结果时，应合并。消费者：当前最佳实践 D。
- **边界与区别**：Google 材料属于通用工程指南；将审查单元用于 AI 任务粒度属于教学迁移。任务、会话、提交可有不同边界，模型能力与工具条件变化时可调整执行批量。Anthropic 2026 年实验已随模型变化调整上下文重置策略，仍保留按功能推进和分轮验收，不能把“一项任务对应一次会话”固化为普遍规则。[S13](#s13) 当前 C 解决按什么业务边界切，D 解决何时停止细拆，E 解决如何抽出共享前置并划分依赖边界。
