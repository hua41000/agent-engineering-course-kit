# 高信号密度的上下文工程：调研结论

调研日期：2026-10-15。面向《企业级Agent工程架构实战营》第 08 课，聚焦 AI Coding 中“此刻需要读什么、保留什么、移出什么”。课堂条目见 [best_practices.md](best_practices.md)。

## 一线实践中可以提炼的技巧

### 1. 给地图与入口，沿当前问题逐步读取

**来源事实：** Anthropic 描述了 Claude Code 的混合方式：预先提供项目说明，再通过文件搜索按需获取材料。Cursor 则把长工具结果和历史记录保存为可检索文件，减少一次性注入。[S1](#s1)、[S2](#s2)

**教学结论：** 先提供当前任务、相关目录和关键入口，再沿调用关系读取实现、测试与契约。文件位置只是导航，Agent 仍须打开核实。必要的业务限制应直接给出；藏在无法访问的资料中会造成信息缺口。按需检索会增加工具往返，小项目的一份短文件可以直接读完。对应最佳实践 A、B。

### 2. 精简的前提是覆盖关键依赖

**真实案例：** Dex 在 BAML 缺陷修复中比较了有代码研究和没有研究的方案。他报告，研究帮助方案选到更合适的修改位置与测试方式；首次研究曾错误判断缺陷不存在，人工复核后重做。[S3](#s3) 对应 PR #2259 确已于 2025-08-05 合并，修改了测试块的语义校验。[S4](#s4)

**反例：** 同一作者尝试从 Parquet Java 移除 Hadoop 依赖时失败，自述原因包括依赖链研究过浅。两段复盘说明：错误信息与关键遗漏都能破坏后续执行。[S3](#s3)

**教学结论：** 搜索应覆盖能影响本次判断的调用链、约束和测试惯例，读到能够解释问题为止。“研究过”不能代替核验，合并记录也无法单独证明某种工作流带来了因果收益。对应最佳实践 B、D。

### 3. 常驻规则保持短，变化的事实引用原件

**来源事实：** HumanLayer 分享其根级 `CLAUDE.md` 较短，任务专用说明按需加载，建议用代码位置指向权威上下文，减少容易过期的复制片段。[S5](#s5)

**教学结论：** 常驻文件适合项目入口、通用约束、验证方式；模块细节放在对应文档和代码中。资料之间的冲突需要说明：当前实现由源码和运行结果确认，目标行为由已批准需求确认，两者不一致可能正是待修复的问题。这一“现状／目标”的区分属于课程应用建议。对应最佳实践 A、C。

### 4. 纠正错误判断，同时保留失败证据

**来源事实与观点：** Drew Breunig 在 O’Reilly 播客约 11:13 解释，错误事实被留在长任务上下文中，会继续干扰判断；互相冲突的信息也会影响输出。[S6](#s6) Manus 的工程复盘强调保留失败动作与观察，让后续步骤知道哪些尝试已经失败。[S7](#s7)

**教学结论：** “数据库连接失败”这样的真实观察值得留下；“所以一定是密码错了”这样的未验证判断要标为假设。推翻假设后，同步纠正工作摘要中的相关结论，保留失败条件和证据路径。这样可同时减少错误事实传播和重复踩坑。对应最佳实践 D、E。

### 5. 大结果先落盘，当前窗口保留定位线索

**来源事实：** Cursor 将长工具响应保存为文件供后续读取，避免简单截断导致信息永久丢失；Anthropic 的工具工程经验支持分页、范围选择、过滤以及按需返回精简／详细字段。[S2](#s2)、[S8](#s8)

**教学结论：** 搜索结果、日志与大型 JSON 先按任务筛选。保留时间范围、关键内容、必要标识和原件路径，让 Agent 能继续追查。原件必须实际可访问；“已保存”但没有路径无法完成交接。对应最佳实践 F、G。

### 6. 测试输出精简，结果与诊断保真

**来源事实：** HumanLayer 在日常开发及客户 Maven／Gradle 项目中使用输出包装：成功返回短消息，失败展示诊断。Dex 特别指出，直接截取测试输出可能漏掉关键报错，迫使人重新运行耗时测试。[S9](#s9)

**教学结论：** 保存真实退出状态和完整输出，成功给出检查范围，失败提取首个相关诊断并提供完整日志入口。不要让过滤操作掩盖原命令失败。“只看到通过的日志片段”不足以宣称检查通过。对应最佳实践 G。

### 7. 跨会话交接当前状态，压缩保留回查能力

**来源事实：** Anthropic 的压缩实践保留决策、未解决问题和实施细节，并提醒过度压缩会丢失后续所需信息。[S1](#s1) Manus 的压缩设计保留文件路径或 URL，便于恢复原内容。[S7](#s7)

**教学结论：** 交接写清目标、当前改动、已验证结果、未解决问题与下一步；完整日志和原始记录留在窗口之外。摘要中的关键判断必须能回到源码、运行记录或用户决定。无需追求固定字数或固定上下文占用率。对应最佳实践 H、I。

### 8. 工具定义也占上下文，优化方式取决于工具实现

**来源事实：** Cursor 按需读取 MCP 工具描述；Manus 则报告，运行中频繁增删工具定义会干扰缓存和历史动作的理解，采用另一套工具可用性控制方式。[S2](#s2)、[S7](#s7)

**教学结论：** 两种实现有不同前提。使用现成工具时，可优先选择该工具原生支持的发现机制，减少无关连接；自建系统时，需要连同缓存、工具历史与正确率一起验证。不能把“每轮动态增删工具”写成所有系统的通用建议。对应最佳实践 J。

## 仍需课堂演示验证的部分

本次完成公开材料核验，尚未在本仓库测量上下文长度、成功率或 token 节省。最佳实践中的 GoodCase／BadCase 均标记为教学示例。带错误摘要的交接、长日志裁剪及不同工具配置的收益，需要用同一任务与相近环境实际比较；当前资料支持做法与适用条件，不承诺收益数字。
