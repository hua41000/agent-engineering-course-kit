Hooks实战经验

用 4 项实践，把自动格式化、操作约束、上下文恢复与每日复盘接入研发工作流。

全部 4 条实践

四个企业级 AI Coding Hook 最佳实践，分别解决：机械工作自动化、安全操作约束、长任务上下文恢复、研发经验持续积累。

事件名以 Claude Code 为例。以下正反案例与每日复盘结果均为教学示例；Hook 机制依据官方文档核对，未在本仓库安装或运行这些 Hook。

A

最佳实践 A：修改后自动格式化

#A
使用 Hook

PostToolUse，匹配 Edit|Write。

Agent 每次通过编辑工具修改代码后，自动调用项目已有的格式化工具，只处理本次变更的文件，消除机械性的格式问题。格式化本身无需额外模型推理，可减少格式检查导致的 CI 失败和人工返工。

GoodCase · 推荐做法

Agent 修改 src/orders/order-service.ts 后，Hook 自动执行：

npx prettier --write src/orders/order-service.ts

Python 项目则调用 ruff format。使用项目已安装的工具，成功时静默，失败时返回具体错误。

BadCase · 避免这样做

每修改一个文件就格式化整个仓库，制造大量无关 diff；或者启动另一个 Agent 对代码进行风格优化，把确定性工具可以完成的工作变成一轮额外的模型推理。

参考依据：

官方指南提供 PostToolUse 配合 Edit|Write 的格式化示例。该匹配范围不覆盖 Bash 等工具产生的全部文件变更；格式化失败的反馈仍可能进入模型上下文。Claude Code Hook 指南

B

最佳实践 B：高风险操作执行前拦截

#B
使用 Hook

PreToolUse，匹配 Bash 等工具；保护文件时也需覆盖 Edit|Write。

在 Agent 执行命令之前，对少数明确禁止、误操作代价高的行为进行确定性检查。命中时直接阻断，并返回可执行的替代方案。优先治理团队真实发生过的高风险操作，不构建庞大的命令黑名单。

GoodCase · 推荐做法

Agent 准备执行：

git push origin main

Hook 识别到直接推送主分支，拒绝执行，并返回：

当前仓库禁止直接推送 main。请创建功能分支并通过 PR 合并。

类似地，可拦截删除受保护目录、直接修改已执行的数据库迁移文件等操作。承担门禁职责的 Hook 使用同步检查，并配置失败时阻断。

BadCase · 避免这样做

对所有 Bash 命令调用 LLM 做安全审查，导致每次执行测试、查看文件都产生额外延迟和 Token 成本。

或者只匹配字符串 rm -rf 就认为已经建立完整安全防线。Hook 应作为操作约束，不能替代沙箱、权限控制和仓库分支保护。

参考依据：

PreToolUse 可在动作执行前拒绝；异步检查不能承担阻断。检查器故障时的 onFailure: "block" 需要 Claude Code v2.1.295 及以上，部署时应核对版本并验证故障行为。Claude Code Hook 参考

C

最佳实践 C：自动恢复长任务上下文

#C
使用 Hook

SessionStart；PreCompact 可选。

在新会话启动、会话恢复或上下文压缩后，自动加载当前任务的必要状态，包括任务目标、执行进度、关键决策、待办事项和必要的文件入口，减少重复探索和约束遗忘。

通过持久化任务状态恢复上下文，避免每次重新总结全部历史会话。主 Agent 在执行过程中更新状态文件；SessionStart 负责加载，PreCompact 可用于压缩前补存尚未持久化的记录。

GoodCase · 推荐做法

Agent 正在执行跨天的订单状态迁移，已经完成 Schema 变更与兼容代码，历史数据尚未回填。

第二天启动 Claude Code 时，Hook 读取任务状态，注入：

当前任务：订单状态字段迁移
已完成：Schema 变更、兼容代码
待完成：历史数据回填、回归测试

关键约束：
- 不得直接修改已执行的迁移文件
- 历史数据迁移必须支持断点续跑

任务入口：
tasks/order-status-migration.md

Agent 可以继续工作，无须重新阅读大量历史会话。

BadCase · 避免这样做

每次启动会话都读取全部历史聊天记录、所有 PRD、全部技术方案和 Skill 文件，导致上下文膨胀、启动成本增加，甚至让过期信息影响当前任务。

参考依据：

SessionStart 的 startup、resume、compact 等来源覆盖启动、恢复与压缩后的上下文注入；PreCompact 在压缩前触发。首轮工作依赖的状态应先加载完成。Claude Code SessionStart · PreCompact

D

最佳实践 D：每日自动复盘与记忆进化

#D
使用 Hook

SessionStart；跨天持续会话可选用 UserPromptSubmit 补充触发。

每天首次使用 Coding Agent 时，Hook 检查上次成功处理的位置，发现新增历史会话后，异步启动复盘任务。分析昨天或上次成功处理以来的工作记录，完成工作总结、长期记忆更新、个人偏好提炼、失败经验分析，以及 Skill 优化建议生成。

Hook 作为触发器，复杂分析交给后台 Agent。每天最多创建一个复盘作业，失败后恢复同一作业；用处理位置和结果记录避免重复处理历史内容。

复盘产物

产物 具体内容 建议去向
工作 Summary 昨天完成的需求、未完成任务、关键决策和遗留问题 每日工作摘要
长期记忆 已确认的架构事实、技术决策、项目约束 仓库级个人记忆
个人偏好 用户反复表达的编码习惯、设计偏好、Review 和 Verify 偏好 个人偏好记忆
经验教训 失败原因、人工纠正、有效解决方法、重复出现的问题 经验库、BadCase 库
Skill 进化 根据高频错误提出 Skill 规则、验证脚本或工作流补丁 Skill 优化候选，审核后应用

GoodCase · 推荐做法

用户当天第一次打开 Claude Code，SessionStart Hook 检测到当天尚未复盘，并发现未处理的历史会话，于是启动后台分析任务。

AI Coding 每日复盘

示例 · 2026-10-17 工作记录

昨日工作总结

完成订单幂等功能和接口测试；数据迁移任务仍有历史数据回填待执行。

新增个人偏好

用户两次明确要求技术方案先提供核心实体类型和领域模型骨架，再展开实现细节。

新增经验教训

订单幂等测试遗漏并发重复请求，人工验收时发现问题。

Skill 优化建议

为 Verify Skill 增加规则：涉及幂等、去重的需求，覆盖并发重复请求及最终业务结果验证。

记忆更新

  • 1 条明确的个人偏好已写入个人记忆。
  • 1 条 Skill 补丁进入待审核列表。

用户无须主动发起复盘。下一次执行相似任务时，已确认的偏好可以发挥作用；高风险规则变更经审核后生效。

BadCase · 避免这样做

每次启动 Agent 都重新分析所有历史会话，重复消耗大量 Token。

把模型推断出的偏好直接写入全局规则，把一次临时操作当成长期习惯；或者让后台 Agent 每天自动重写全部 AGENTS.md 和 Skill，导致约束不断膨胀、相互冲突。

明确事实可以自动沉淀，推断性结论需要证据，团队公共规则与 Skill 变更需要审核。

执行流程

SessionStart / UserPromptSubmit
     ↓
检查当天作业、上次成功处理位置和新增会话
     ↓
无新增 / 已完成 → 静默退出
有新增 → 获取任务锁，创建或恢复当天作业
     ↓
后台增量读取历史会话
     ↓
总结 / 记忆提炼 / 经验分析
     ↓
去重、验证、分类
     ↓
更新记忆 / 生成 Skill 补丁候选
     ↓
保存执行结果，成功后推进处理位置

实现要点

  • 触发脚本只做轻量检查与投递，由后台任务执行复盘；“每日”指当天首次使用时触发。
  • 按日期与处理范围建立稳定作业标识；并发启动用锁防重，失败沿用原作业恢复，写入去重。
  • 后台复盘会话跳过同一触发器，避免递归启动；限制单次处理量、模型预算和重试次数。
  • 记忆保留证据与适用范围，按项目归档；团队公共规则和 Skill 补丁审核后应用。
参考依据：

SessionStart 可通过 command Hook 投递后台作业，不能直接配置为 agent Hook。每日去重、增量处理、记忆分类与审核流程是本课程方案，需要自行实现和验证。Claude Code SessionStart · 后台进程说明

四项实践汇总

最佳实践 Hook 主要价值 执行成本
A. 修改后自动格式化 PostToolUse 消除机械性返工 低
B. 高风险操作执行前拦截 PreToolUse 防止危险操作 极低（本地确定性检查）
C. 自动恢复长任务上下文 SessionStart、可选 PreCompact 降低上下文恢复成本 低～中
D. 每日自动复盘与记忆进化 SessionStart、可选 UserPromptSubmit 积累记忆、经验与研发资产 中～高，异步执行

成本为教学场景的相对判断，取决于脚本、数据量和模型配置。

两类基础能力

  • A、B：实时工程约束型 Hook。 高频触发，必须足够快、足够确定，尽量不依赖模型。
  • C、D：上下文与持续进化型 Hook。 上下文恢复与复盘按需执行；即使使用 UserPromptSubmit 高频检查，也只做轻量判断。复杂分析可以调用模型，并具备状态管理、增量处理、去重和成本控制。

D 可作为企业级 AI Coding Harness 的重点建设方向：在完成需求之外，把每天的研发活动持续转化为下一次开发可复用的记忆、经验与 Skill 改进。

案例与复盘产物均为教学示例；未在本仓库安装或运行这些 Hook。
