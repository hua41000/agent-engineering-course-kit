# 首版功能用例

首版采用轻量检查，不要求复杂证据或大规模评测。

| 请求 | 观察重点 |
|---|---|
| 在已有 Python 指标服务上增加开放异常分析 | 先理解查询接口，补问路径、检查和维护约束；可建议 Autonomous-first Hybrid，保留现有查询服务 |
| 自动退款，但还没有受控写入接口 | 明确建议阶段与执行阶段；先交付草稿，指出尚未满足真实执行目标 |
| 单次提取字段，已有确定格式 | 从 LLM Feature 或简短 Chain 起步，不增加多个 Agent |
| 接收网页导出的 JSON，改为 TypeScript | 原业务条件保留，更新框架候选并重新生成报告 |

脚本验证：从源码及解压后的包分别执行 template、questions、recommend；检查五个输出文件存在，重复写入同目录应拒绝覆盖。共享规则基本用例在产品 tests/core.test.mjs 中执行。

## 通用模型基本场景

- 自定义领域“园区环保设施运营”：从任务路径与接口条件提出方案，不依赖内置案例。
- 保留核心的已有 Workflow：推荐外围扩展或局部探索，说明复用状态和身份体系。
- 改造切为新建：保留隐藏回答供恢复，但其瓶颈和迁移规则不影响新建输出。
- 关键数据缺失、硬实时约束或高影响全自动目标：分别收窄当前范围、移出实时关键路径、保留必要复核。

这些边界由产品 tests/core.test.mjs 的基本检查覆盖。

## 多需求组合与旧会话迁移

- 同时要求知识咨询、经营分析、事件触发和后台批量：以多选数组保存，报告保留会话、事件、队列、检索与结构化查询能力。
- 固定流程、开放调查和校验计划并存：输出分别对应的路径与模式，追问各任务的归属，不将所有需求强行放进一个循环。
- 自动检查加人工复核、只读加写入：保留双重检查，授权未具备时写入保持草稿。
- Python 与 TypeScript 服务共存：候选注明适用语言；旧单选 Session 自动迁移，导出后再导入不丢需求。
- “无需外接”与 API 同时出现在导入文件中：明确报错，要求澄清；问卷内切换排他选项时移除冲突项。
